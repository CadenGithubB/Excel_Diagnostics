Excel diagnostics viewer

Search, filter and line up everything in a bundle collected by excel_diagnostics.sh, without the logs leaving this computer.

Drop an Excel_Diagnostics_….zip here or the unzipped folder, or individual log files
Nothing to open yet? Run excel_diagnostics.sh on the Mac where Excel is misbehaving. It makes the zip this page reads.
Working in a terminal, or handing this to an agent? excel_diagnostics_cli.mjs searches a bundle without a browser, and each command says what to run next.
  • Nothing is uploaded. The page has no server side, and its security policy blocks every network request, so it could not send the logs anywhere. You can save this page and use it offline.
  • One timeline. The macOS unified log, Excel's own diagnostics, AutoUpdate, OneDrive, install history, sleep and wake, and each crash or hang report are merged by time and shown in the time zone of the Mac they came from.
  • Large captures are fine. Logs are read from disk as you search instead of being loaded into memory. A bundle over about 1 GB opens fastest from its unzipped folder.

The list on the left filters by severity, source, tag and process: click a value to show only it, or its − to hide it. The counts beside the other values show what choosing them would give.

Under each severity are the levels the logs themselves use. macOS writes Default, Info, Debug, Error and Fault; Excel writes Medium, Monitorable (worth watching, not a failure) and Unexpected (something went wrong). Choosing a severity chooses all of its levels.

On the chart, drag to zoom in to a time span, right-click to zoom out, and click to jump the list to that moment.

excel_diagnostics.sh

The collector. Run it on the Mac where Excel is slow, hanging or crashing. It gathers Excel's logs, crash and hang reports and the macOS log into an Excel_Diagnostics_….zip on the Desktop, which is what this page reads.

In Terminal, with the script saved to Downloads:

sudo bash ~/Downloads/excel_diagnostics.sh

It asks what to collect before it starts. Add --help to see every mode and option.

excel_diagnostics_cli.mjs

  
The command-line tool. It searches a bundle from a terminal with the same engine as this page, for working without a browser or for handing the job to an agent. Every command prints what it searched, what it found and a list of commands that follow on. It reports what the logs hold and leaves the conclusions to the reader. Nothing is uploaded.

  
It is one file and needs Node 20 or later, or Deno 2. With it downloaded:

  
node excel_diagnostics_cli.mjs ~/Desktop/Excel_Diagnostics_collect_20260310_091500.zip
node excel_diagnostics_cli.mjs help

  
The first line says what that bundle holds and where to start; put your own zip or unzipped folder in its place, or the word sample for made-up data. With Deno, write deno run -A in place of node.

  

    
summaryWhat the bundle holds and where to start. Runs when no command is given.

    
search WORDSThe entries that match, oldest first. Takes the same search syntax as this page, plus --from, --to, --around and --min-severity.

    
count, histogramHow many entries match per process, tag, source or severity, and when they were logged.

    
show ID, context IDOne entry in full, and everything every source logged around it.

    
reports, memoryThe crash, hang and jetsam reports, and the memory figures the bundle recorded.

    
files, cat PATHThe files in the bundle, and the text of one.

    
export --out FILEEvery matching entry as a tab-separated file.

    
help examplesStep-by-step commands for common jobs, such as seeing what led up to a crash report.
